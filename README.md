## Проблема поиска поверхности атаки
### Определение поверхности атаки

Поверхность атаки — это совокупность всех возможных точек входа, через которые злоумышленник может получить несанкционированный доступ к информационной системе организации или отдельного пользователя. 
Это понятие охватывает все потенциально уязвимые места в цифровой инфраструктуре, 
включая аппаратное и программное обеспечение, сетевые устройства, конечные точки, облачные сервисы, а также человеческий фактор.

Важно понимать, что поверхность атаки — это динамическая концепция. 
Она постоянно меняется по мере того, как внедряются новые технологии. 
Поэтому управление поверхностью атаки — это непрерывный процесс, требующий постоянной адаптации к меняющимся условиям.

### Компоненты поверхности атаки

Основные компоненты поверхности атаки:

- **Сетевая инфраструктура**
  Это включает в себя все устройства, связанные с сетью организации, такие как маршрутизаторы, коммутаторы, брандмауэры, а также сами сетевые протоколы. Каждое из этих устройств может иметь уязвимости, которые могут быть использованы злоумышленниками.

- **Программное обеспечение**
  Все приложения, используемые в организации, от операционных систем до специализированного программного обеспечения, являются частью поверхности атаки. Уязвимости в программном обеспечении — один из наиболее распространенных векторов атак.

- **Аппаратное обеспечение**
  Физические устройства, такие как серверы, рабочие станции, мобильные устройства, IoT-устройства, также являются потенциальными точками входа для атакующих.

- **Облачные сервисы**
  С ростом популярности облачных вычислений, многие организации переносят свои данные и приложения в облако. Это создает новые вызовы для безопасности, так как контроль над инфраструктурой частично передается провайдеру облачных услуг.

- **Человеческий фактор**
  Сотрудники организации, подрядчики, партнеры — все они могут стать «слабым звеном» в системе безопасности. Социальная инженерия, фишинг, использование слабых паролей — все это увеличивает поверхность атаки.

- **Данные**
  Сами по себе данные организации, особенно если они не зашифрованы или неправильно хранятся, могут стать целью атаки.

- **API и веб-сервисы**
  Интерфейсы прикладного программирования (API) и веб-сервисы, которые организация предоставляет внешним пользователям или использует сама, также являются частью поверхности атаки.

В данной работе будет рассмотрен последний компонент.

### Базовые инструменты для анализа кода без построения поверхности атаки
GDB/LLDB: Отладчики, которые можно использовать с плагинами для отслеживания данных (например, Intel Pin, Frida), но менее автоматизированы для построения всей поверхности.

#### OWASP ZAP

Сканер для поиска уязвимостей в веб-приложениях

В OWASP ZAP существуют 4 режима сканирования:
- Standard Mode — обычное сканирование;
- Safe Mode — безопасное сканирование, позволяющее выполнять только те действия, которые не смогут навредить системе. В этом режиме не используются атаки на целевой сайт;
- Protected Mode — защищенное сканирование, позволяющее имитировать потенциально опасные уязвимости;
- ATTACK Mode — режим атаки, позволяющий, помимо сканирования, также выполнять атаки на потенциальный сайт/приложение.

#### Natch
Тезисно:
- Динамический анализ: Анализирует приложение во время работы, помещая его в виртуальную машину (QEMU).
- Отслеживание данных: Использует технологию "помеченных данных" (taint analysis) для отслеживания, как входные данные (сетевые пакеты, файлы) перемещаются по системе.
- Системный уровень: Анализирует не только приложение, но и ядро ОС, драйверы благодаря QEMU.
- Результат: Строит граф потоков данных и функций, которые обрабатывают ввод, то есть "поверхность атаки".
- Интеграция: Может встраиваться в CI/CD для тестирования безопасности

Подробнее:
Для фильтрации оставляет только сущности, обрабатывающие небезопасные данные. 
Для этого:

Помечаются входные данные из недоверенных источников (файлы, сеть).
Средствами эмулятора отслеживается распространение меток по памяти виртуальной машины.
Фиксируется, где обрабатывались помеченные данные — это и есть искомая поверхность атаки.
Техническая основа:
Построен как набор плагинов для полносистемного эмулятора QEMU, который:

Поддерживает множество архитектур (x86, ARM, MIPS, RISC-V).
Самостоятельно обладает минимальными возможностями анализа (только gdb-сервер и логирование инструкций).
Решение проблемы производительности:
Инструментирование кода значительно замедляет эмуляцию.
Решение: Использование детерминированного воспроизведения (replay):

Сначала записывается тестовый сценарий работы системы средствами QEMU.
Затем сценарий воспроизводится с подключенными плагинами Natch.
Это исключает влияние задержек от анализа на поведение гостевой системы 
(критично для сетевых взаимодействий и часов реального времени).

Примерный алгоритм получения поверхности атаки:
1) Запись тестового сценария средствами QEMU.
2) На этапе воспроизведения готового сценария выполняются следующие шаги:
   1) загрузка плагина natch;
   2) ожидание загрузки гостевой системы до интересующего аналитика момента работы системы;
   3) включение анализа помеченных данных (если он не был включен автоматически через конфигурационный файл);
   4) автоматический сбор информации о потоках данных в тестовом сценарии;
   5) сохранение собранных данных и завершение работы эмулятора.

Ищет:

### Sourcetrail
Интерактивный анализатор и визуализатор кодовой базы. Помогает разработчикам понимать и навигировать по незнакомому коду.

Строит интерактивные графы.
Принцип работы:
1. Индексация кода
   Парсинг исходников — построение AST (Abstract Syntax Tree)
   Извлечение семантической информации:
   - Объявления функций/классов
   - Вызовы функций
   - Наследование
   - Включения файлов
   - Использование переменных
   - Создание базы данных индекса (обычно в 2-3 раза больше исходного кода)
2. Визуализация и навигация
   - Динамическое построение графов по запросу
   - Связь графов с исходным кодом (клик на узле → переход к коду)
   - Фильтрация и поиск по различным критериям

Ограничения:
- Медленная индексация для очень больших проектов
- Сложности с препроцессором C/C++ (условная компиляция)
- Ограниченные возможности кастомизации визуализации

### Intel VTune Amplifier
Инструмент для анализа и оптимизации приложений.

Типы доступного анализа:
1. Hotspot Analysis (Анализ "горячих точек")
   Цель: Найти функции, которые потребляют больше всего времени CPU
2. Microarchitecture Analysis
   Цель: Понимание как приложение использует микроархитектуру процессора 
3. Memory Access Analysis
   Цель: Анализ паттернов доступа к памяти
4. Threading Analysis
   Цель: Анализ многопоточных приложений
5. I/O Analysis
   Цель: Анализ операций ввода-вывода
6. GPU Offload Analysis
   Цель: Анализ вычислений на GPU

Принцип работы:
1. Настройка и конфигурация
2. Сбор данных:
   - семплирование по событиям
   - статистическое профилирование
   - сбор графа вызовов
   - раскрутка стека
3. Построение визуализации:
   - временная шкала выполнения
   - иерархия вызовов как пламя
   - тепловая карта использования памяти
   - гистограмма использования CPU
   - граф потока вызовов

### PATHFINDER
Анализатор путей выполнения и инструмент символьного исполнения, обычно используемый для анализа уязвимостей и покрытия кода.

Основной принцип работы:
1. Подготовка и инициализация
   1. Загрузка и парсинг кода
   2. Инициализация символьного состояния
   3. Определение символьных входных данных
2. Символьное исполнение
   1. Основной цикл исполнения
   2. Обработка различных типов инструкций
      - Арифметические операции
      - Условные переходы
      - Вызовы функций
3. Управление состоянием и ветвлением
   1. Клонирование состояния
   2. Разрешение ветвления (forking)
4. Решение ограничений
   1. Сбор ограничений пути
   2. Проверка выполнимости (Satisfiability)
   3. Генерация тестовых данных
5. Анализ и отчетность
   1. Анализ покрытия кода
   2. Поиск уязвимостей
